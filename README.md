# Halyk AI Challenge — инструкция по запуску

Агент читает PDF-договоры + аудит/KYC-документы + реестр транзакций и для
каждого ковенанта (6.1/6.2/6.3) каждого заёмщика определяет `status`,
`actual`, `evidence_txn_id`. На выходе — `submission.json` строго по формату
`submission_template.json`.

Как устроена архитектура и почему без RAG — см. `ARCHITECTURE.md` в этой же папке.

**Проект построен по гексагональной архитектуре (Ports & Adapters):**

- domain/ — модели и порты (интерфейсы), без зависимостей от внешних библиотек.
- application/ — use cases, работают только через порты.
- adapters/outbound/ — реализации портов: pdfplumber (PDF), pandas (леджер), Anthropic / OpenRouter / TokenRouter (LLM), JSON-файлы.
- adapters/inbound/ — CLI (run.py), собирает адаптеры и запускает use case.

Любую технологию (провайдера LLM, способ парсинга PDF и т.д.) можно заменить, не трогая бизнес-логику.

---

## 1. Что нужно перед запуском

- Docker + Docker Compose
- Ключ от одного из провайдеров LLM (см. раздел 3 — поддерживается несколько)
- Датасет от организаторов, распакованный в папку `agentic-bank-public/` **рядом** с `docker-compose.yml`:

```
halyk_agent/
├── docker-compose.yml
├── Dockerfile
├── .env                        ← создать самому, см. ниже
├── agentic-bank-public/        ← сюда весь датасет ЦЕЛИКОМ
│   ├── master_ledger_2025.csv
│   ├── documents/               ← ВСЕ файлы, без исключений
│   ├── submission_template.json
│   └── ground_truth.json        (есть только для открытого датасета)
├── output/                      ← создастся само, туда упадёт submission.json
└── cache/                       ← создастся само (кэш распарсенных PDF)
```

**Важно:** кладите в `documents/` весь архив документов целиком. Заранее
угадать, какие файлы нужны какому сценарию, невозможно — имена файлов это
непрозрачные хеши, а нужные supporting-документы (аудит/KYC) у разных
сценариев разные. Мы проверяли это на практике: удаление "лишних" файлов
для экономии токенов ломает точность именно тех расчётов, для которых
удалённый файл был нужен (см. `ARCHITECTURE.md`, раздел про P1/P2).

## 2. Настройка `.env`

Скопируйте `.env.example` в `.env` и заполните под свой провайдер (см.
раздел 3 ниже, какие именно переменные нужны). Общие для всех провайдеров:

```
HALYK_TEAM_NAME=ваша-команда
HALYK_CONTACT_EMAIL=you@example.com
```

`.env` уже в `.gitignore` — не попадёт в git-коммит случайно.

---

## 3. Провайдеры LLM — какие переменные задавать

Провайдер определяется **автоматически** по тому, какие переменные заданы
в `.env` — ничего в коде менять не нужно.

| Провайдер | Переменные в `.env` | Когда используется |
|---|---|---|
| **Anthropic API** | `ANTHROPIC_API_KEY`, `HALYK_AGENT_MODEL=claude-fable-5` (или другая) | Если ничего из вариантов ниже не задано |
| **TokenRouter** (tokenrouter.com) | `TOKENROUTER_API_KEY`, `HALYK_AGENT_MODEL=<id из вашего кабинета>` | Автоматически, если задан `TOKENROUTER_API_KEY` |
| **OpenRouter** (openrouter.ai) | `OPENROUTER_API_KEY`, `HALYK_AGENT_MODEL=moonshotai/kimi-k3` (с `/`) | Автоматически, если задан `OPENROUTER_API_KEY` и в имени модели есть `/` |
| **Modal / любой другой OpenAI-совместимый шлюз** | `HALYK_API_BASE_URL=https://...modal.direct/v1`, `HALYK_API_KEY` (можно оставить пустым для Modal Auto Endpoint без авторизации) | Автоматически, если задан `HALYK_API_BASE_URL` |

Явно переопределить выбор (обычно не требуется):
```
HALYK_PROVIDER=anthropic | openrouter | tokenrouter | custom
```

**Важно про Modal:** для этого провайдера бюджетный контроль по `$` не
работает (тарификация по времени работы контейнера, а не по токенам) —
`run.py` сам это обнаруживает и явно предупреждает в логе. Следите за
расходом в личном кабинете Modal вручную.

### Проверка ключа/подключения без трат на сам расчёт

```bash
docker compose build
docker compose run --rm agent python src/check_provider.py
```

Печатает, какой провайдер/модель/ключ определились, и делает один лёгкий
запрос к `/models`, чтобы подтвердить, что ключ и `base_url` рабочие —
до того как тратить деньги на настоящий расчёт по всем сценариям.

## 4. Запуск

```bash
# Сборка образа (нужно повторять при каждой правке .py-файлов, НЕ нужно при правке .env)
docker compose build --no-cache

# Проверка без трат: полный проход по пайплайну, без единого вызова LLM
docker compose run --rm agent --dry-run

# Полный прогон
docker compose run --rm agent

# Результат появится на хосте в ./output/submission.json
```

**Важно про `--entrypoint`:** если нужно выполнить внутри контейнера что-то
кроме `run.py` (например, `env`, `python другой_скрипт.py`), обязательно
переопределяйте entrypoint явно — иначе Docker подставит вашу команду как
аргумент в `run.py` и вы получите `unrecognized arguments`:
```bash
docker compose run --rm --entrypoint python agent src/check_provider.py
docker compose run --rm --entrypoint sh agent -c "env | grep API"
```

## 5. Локальный скоринг (только для открытого датасета — там есть `ground_truth.json`)

```bash
docker compose run --rm agent python src/validate.py \
    --submission /app/output/submission.json \
    --ground-truth /app/data/ground_truth.json
```

Печатает балл по каждой ячейке (0-1) по формуле из `CASE.md` и итоговую
сумму — так можно проверить качество агента до появления приватного
датасета 9 августа.

---

## 6. Экономный тест на одном сценарии (без урезания документов!)

Если нужно проверить/отладить конкретный сценарий, не тратя деньги на
все 12 — **не удаляйте PDF-файлы**. Вместо этого временно сократите
список сценариев в `submission_template.json`:

```bash
# сохранить полный шаблон
cp agentic-bank-public/submission_template.json agentic-bank-public/submission_template_full.json
```

Откройте `submission_template.json` и оставьте внутри `"answers"` только
нужный сценарий (например, только `"P2"`), остальные ключи удалите.
Запустите как обычно — пайплайн обработает только этот один сценарий
(один вызов LLM вместо двенадцати), а `documents/` при этом останется
нетронутым, и агент увидит все нужные supporting-документы.

**После теста верните полный шаблон:**
```bash
mv agentic-bank-public/submission_template_full.json agentic-bank-public/submission_template.json
```

## 7. Resume и защита от повторной оплаты

`run.py` при каждом запуске проверяет, существует ли уже файл `--output`:
если да — сценарии, у которых **все три** ковенанта уже заполнены,
**пропускаются** и не пересчитываются повторно. Сохранение происходит
**после каждого сценария**, а не только в конце — если прогон прервётся
(ошибка, кончился бюджет, вы сами остановили), уже посчитанные и
оплаченные сценарии не потеряются.

Чтобы пересчитать всё заново, игнорируя предыдущий результат:
```bash
docker compose run --rm agent --no-resume
```

Жёсткий потолок бюджета за прогон (работает только для провайдеров с
токенной тарификацией, не для Modal — см. раздел 3):
```bash
docker compose run --rm agent --max-spend 2.0
```

## 8. Частые ошибки и что они значат

| Сообщение в логе | Причина | Что делать |
|---|---|---|
| `Unterminated string...` при парсинге JSON | Ответ модели обрезался по `max_tokens` | Увеличить `max_tokens` в `reason.py` |
| `401 Unauthorized` | Неверный/отозванный ключ, либо ключ не того провайдера (например, ключ TokenRouter подставлен в `OPENROUTER_API_KEY`) | Проверить `docker compose run --rm agent python src/check_provider.py` |
| `RemoteDisconnected` / `Connection aborted` | Обрыв соединения, типично для холодного старта Modal-контейнера | Пайплайн сам делает 3 попытки с задержкой (10с/30с/60с) — если не помогает, контейнер может падать под конкретным промптом, смотрите логи Modal |
| `unsupported operand type(s) for +=: 'float' and 'NoneType'` | Провайдер без токенной тарификации (Modal) - старая версия `run.py` не умела это обрабатывать | Уже исправлено в текущей версии `run.py` |
| `unrecognized arguments` при `docker compose run --rm agent <команда>` | Забыли `--entrypoint`, команда подставилась как аргумент в `run.py` | См. раздел 4 выше |
| Резкое расхождение `actual` с ожидаемым при в целом верном `status` | Скорее всего, не хватает supporting-документа (аудит/KYC) с нужной переклассификацией | Проверить, что `documents/` содержит **все** файлы датасета, не урезанные |
